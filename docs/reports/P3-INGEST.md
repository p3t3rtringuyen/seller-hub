## Needs from others (nothing blocks the merge)

1. **API layer / P3-IDENTITY** — `GET /v1/seller-accounts/{id}/sync-health` (bind `getSyncHealth` from `@seller-hub/ingestion`)
   and `POST …/sync/{syncKey}/refresh` (bind `scheduler.requestRefresh`), their OpenAPI contract, permissions `sync.read`
   and `sync.refresh`, and a nav entry (`apps/web/features/platform-ingestion/sync/sync.nav.ts` + message file). The
   screen calls the BFF paths above and shows its error state with Retry until they exist; its copy is in
   `settings/sync/copy.ts` and should move into the message catalogue.
2. **P3-IDENTITY** — a `CredentialSource` backed by the vault: pass it to `startIngest({ credentials })`
   (`missingVaultCredentialSource` is the placeholder; live runs fail with a clear message). Optionally its own
   `SellerDirectory`; the default reads `core.seller_accounts`, `core.seller_account_marketplaces`, `core.ads_profiles`
   and `core.connections` read-only with the owner connection.
3. **Command executor (S02)** — after a successful command, call `scheduler.requestRefresh(scope, { syncKey, entityIds })`.
4. **P3-CLIENTS** — Data Kiosk operations are not in the SP allow-list. The family works against `DataKioskPort` and a
   stub; without the client a Data Kiosk definition fails with `kiosk_unavailable` (tested).
5. **Orchestrator** — `modules/example` declares a sync with `family: "example"`. The engine skips that placeholder
   family so the worker boots; delete the module with the rest of the example. The migration discovery
   (`tools/registry/src/discover.ts`) globs only `packages/db/migrations` and `modules/*/migrations`, although the PLAN
   row allows `packages/ingestion/migrations`; extend it if a migration is wanted there.
6. **Infra** — the bucket lifecycle rule (35 d) for `raw/` (ADR-0009) is not code; the worker creates the bucket when
   missing (dev MinIO starts empty).

## Open questions and follow-ups

- **Throttle count** has no column in `ingest.job_runs`; it is kept in `sync_states.cursor.lastRun.throttles`
  (and `cursor.runs[runId]` in flight). A `throttle_count` column (new migration, needs the discovery change in 5) would
  make it queryable per run. The status screen shows the last run's count.
- **Ads report slots**: no lease is held between polls, so two workers may create two reports at once; Amazon's 429 and
  the delay path absorb it. If P3-SMOKE shows the app really is limited to one concurrent report, hold the gate lease in
  Redis keyed by run id and release it on terminal state.
- **XML**: `parseXmlRecords` is a flat-record helper only; a slice that needs attributes or nesting brings a parser.
- **SQS**: no AWS SDK was added (R7 not available); `docs/architecture/ingestion.md` §5 lists the wiring steps.
- **Large reports** are held in memory (documents are decompressed with a 512 MiB cap by the client). Stream parsing is a
  later optimisation; measure with the 100k-SKU report in S06.
- **Stack**: brought down at the end of the task (`pnpm stack:down`); `ads-api-cache-1` was never touched.
