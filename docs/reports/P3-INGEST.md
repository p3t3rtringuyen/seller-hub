## Open questions and follow-ups

- **Throttle count** has no column in `ingest.job_runs`; it is kept in `sync_states.cursor.lastRun.throttles`
  (and `cursor.runs[runId]` in flight). A `throttle_count` column (new migration, needs the discovery change in 5) would
  make it queryable per run. The status screen shows the last run's count.
- **Ads report slots**: no lease is held between polls, so two workers may create two reports at once; Amazon's 429 and
  the delay path absorb it. If P3-SMOKE shows the app really is limited to one concurrent report, hold the gate lease in
  Redis keyed by run id and release it on terminal state.
- **XML**: `parseXmlRecords` is a flat-record helper only; a slice that needs attributes or nesting brings a parser.
- **SQS**: no AWS SDK was added (R7 not available); `docs/architecture/ingestion.md` §5 lists the wiring steps.
- **Large reports** are held in memory (documents are decompressed with a 512 MiB cap by the client). Stream parsing is a
  later optimisation; measure with the 100k-SKU report in S06.
- **Stack**: brought down at the end of the task (`pnpm stack:down`); `ads-api-cache-1` was never touched.
