# seller-hub data model

Task P2-DATA. The database seller-hub owns: tables designed from Amazon's models (the truth about Amazon
objects), the legacy inventory (which fields and app-owned concepts the business uses) and the 23 MVP rows of
`docs/SCOPE.md`. The DDL in `db/design/` becomes the first migrations in P3.

Binding frame: ADR-0004 (tenancy), ADR-0005 (vault), ADR-0008 (ingestion), ADR-0009 (storage), ADR-0011
(commands, rules), `docs/architecture/conventions.md`; decisions D0, D1 c, D4, D5/D60, D11, D53, D55, D57 a,
D62 a, D63 a, D64 a.

| File | What |
|---|---|
| [`mapping.md`](mapping.md) | Every table: source (Amazon model / report / legacy entity / app-owned), column → source field, refresh mode, retention, PII flag; legacy entity coverage |
| `erd-<schema>.md` | Mermaid ER diagram per schema: [identity](erd-identity.md), [core](erd-core.md), [ref](erd-ref.md), [ingest](erd-ingest.md), [ads](erd-ads.md), [catalog](erd-catalog.md), [inventory](erd-inventory.md), [orders](erd-orders.md), [finance](erd-finance.md), [facts](erd-facts.md), [ops](erd-ops.md) |
| `db/design/NN_<name>.sql` | PostgreSQL 16 DDL, applied in file-name order |

## 1. Layers (Postgres schemas)

ADR-0009 decision 1 fixes the schema names. The P2-DATA prompt used older names; the ADR wins:
`raw` → `ingest` (raw payloads live in object storage, only their index is in the DB), `fact` → `facts`,
`app` → `ops` (commands, rules, audit, history) + `core.user_preferences`. Sync state is `ingest.sync_states`,
not `core`.

| Schema | Holds | Tenant? | Owner module (ADR-0001) |
|---|---|---|---|
| `identity` | users, auth methods, sessions, one-time tokens, 2FA secrets; `api_tokens` (tenant-scoped) | global (api_tokens: tenant) | platform-auth |
| `core` | tenants, memberships, role grants, invitations, seller accounts, marketplaces per account, connections, credentials, connect states, Ads profiles, user preferences | tenant | platform-tenancy, platform-connections |
| `ref` | regions, currencies, marketplaces, Ads bid/budget limits | global, read-only | platform (seeded by migration) |
| `ingest` | sync states, job runs, raw object index, push inbox | tenant + seller account | ingestion |
| `ads` | SP mirror: portfolios, campaigns, placement adjustments, ad groups, product ads, targets | tenant + seller account | ads |
| `catalog` | listings, listing issues, catalog item enrichment | tenant + seller account | catalog |
| `inventory` | FBA inventory (current) | tenant + seller account | inventory |
| `orders` | orders and order items without PII | tenant + seller account | orders |
| `finance` | transactions, flattened transaction lines, financial event groups | tenant + seller account | finance |
| `facts` | monthly-partitioned time series (Ads SP daily ×6, sales daily, inventory daily, finance per SKU daily) | tenant + seller account | the module that loads them |
| `ops` | commands, command items, outbox, audit log, change history, automation settings, rules, rule runs | tenant (+ seller account except audit) | platform-commands, automation |
| `pii` | **empty** (D11 = no) | — | later PII slice |

## 2. Conventions applied

- **Names**: snake_case, plural tables, FK `<singular>_id`, instants `*_at` (`timestamptz`, UTC), business dates
  `*_date` / `date` (marketplace-local). Amazon ids are `amazon_<entity>_id text` — never numeric (conventions §1).
- **Keys**: internal PK `id uuid`, UUIDv7 generated by the app (`packages/core`); no DB default on purpose.
  Amazon natural key unique per seller account, e.g. `unique (seller_account_id, amazon_campaign_id)`
  (conventions §2). Ads ids are globally unique in Amazon, so the marketplace is a column, not part of the key;
  SP-API keys that are only unique per marketplace include it (`(seller_account_id, marketplace_id, seller_sku)`).
- **Tenant integrity**: every seller-data table has `tenant_id` and `seller_account_id`. FKs to a seller account
  or a parent row are **composite** `(tenant_id, x_id) → parent (tenant_id, id)`, so a row can never point at
  another tenant's parent even through a bug.
- **RLS** (ADR-0004 decision 5): `core.apply_tenant_rls(tbl)` enables RLS with policy `tenant_isolation`:
  `tenant_id = app.tenant_id AND (app.seller_account_id unset OR seller_account_id = app.seller_account_id)`,
  in both `USING` and `WITH CHECK`. Unset tenant ⇒ no rows (fail closed). Tables whose rows can be tenant-wide
  (`role_grants`, `invitations`, `connect_states`, `user_preferences`, `api_tokens`, `audit_log`) use the
  tenant-only variant. `tenants` and `memberships` also show the current user's own rows (tenant switcher,
  `/v1/me`). Invitation acceptance (no tenant yet) uses one `SECURITY DEFINER` lookup,
  `core.find_open_invitation(token_hash)`. RLS is enabled, not forced: `sh_owner` (owner) runs migrations and
  purges; `sh_app` (NOBYPASSRLS) serves requests. Policies on partitioned parents cover their partitions.
- **Money**: `numeric(18,4)` + `char(3)` currency column next to it (conventions §5). Facts carry `currency` per row.
  Ratios are never stored.
- **Enums**: Amazon values verbatim. `CHECK` constraints only on enums seller-hub **writes** (state, match
  types, target type/level, bid strategy, placement, portfolio budget policy); read-only enums Amazon extends
  often (deliveryStatus, deliveryReasons, transaction types) are plain `text`, so a new Amazon value never
  breaks ingestion. Our own enums are lower_snake (`command status`, `rule mode`).
- **Mirror columns** (ADR-0009 decision 2): `raw jsonb` (last payload, PII stripped), `amazon_created_at`,
  `amazon_last_updated_at`, `synced_at`, `deleted_at` (gone from Amazon / not in the full export; `ARCHIVED` is a
  state, not a deletion), `created_at`, `updated_at` (trigger `core.touch_updated_at`).
- **One table per entity per ad product** (trap 16): `ads.sp_*` now; SB/SD tables (`ads.sb_*`, `ads.sd_*`) arrive
  with ADS-12/13. v1 unifies keywords, product targets, auto targets and negatives at both levels into one
  `SPTarget`, so `ads.sp_targets` holds all of them (legacy had six tables).
- **Facts key on Amazon ids**, not our UUIDs: report rows can arrive before the mirror row; joins use
  `(seller_account_id, amazon_*_id)`.
- **Vendor seam** (D5, D60): `core.seller_accounts.account_type seller|vendor`, `core.ads_profiles.account_type
  seller|vendor|agency`, `ads.sp_ads.sku` nullable (vendors advertise by ASIN), `ref.ads_limits.account_type`.
  No vendor tables in MVP DDL.
- **Regions** (D4): all NA/EU/FE marketplaces are seeded; only US is `is_enabled`. Marketplace time zone and
  currency are data; the linked Ads profile's `timezone` is authoritative for Ads dates.
- **Limits as data** (conventions §5, D59, UX-14): `ref.ads_limits` seeded for SP from
  `refs/amazon-ads/docs/reference/concepts/limits.md`; missing console validation detail is added as rows.

## 3. Partitioning

Monthly native range partitions (ADR-0009 decision 3), name `<table>_pYYYYMM`, created by
`core.ensure_monthly_partitions(parent, from_month, to_month)` (idempotent).

| Table | Partition key | Initial window (`99_partitions.sql`) |
|---|---|---|
| `facts.ads_sp_campaign_daily`, `_ad_group_daily`, `_target_daily`, `_ad_daily`, `_search_term_daily`, `_placement_daily` | `date` (profile-local) | −25 … +3 months |
| `facts.sales_daily`, `facts.inventory_fba_daily`, `facts.finance_sku_daily` | `date` (marketplace-local) | −25 … +3 months |
| `ingest.job_runs` | `created_at` | −1 … +3 months |
| `ingest.raw_objects` | `landed_at` | −1 … +3 months |
| `ops.audit_log` | `occurred_at` | −1 … +3 months |
| `ops.change_history` | `changed_at` | −1 … +3 months |

A daily `maintenance.partitions` job keeps 3 months ahead; backfill jobs call the helper for their window before
inserting (Ads backfill reaches 24 months back, v1 date retention). No DEFAULT partition: a missing partition
fails loudly instead of filling a default that blocks later attaches. Every partitioned PK starts with the
tenant/seller keys and contains the partition key.

## 4. Retention (D64 a — env-configurable)

| Data | Default | Mechanism | Env |
|---|---|---|---|
| Raw payloads (object store) + `ingest.raw_objects` | 35 days | bucket lifecycle + drop partitions | `SH_RAW_RETENTION_DAYS` |
| `ingest.job_runs` | 90 days | drop partitions | `SH_JOB_RUN_RETENTION_DAYS` |
| `ingest.inbox` | done: 35 days; failed: until replayed, max 90 days | delete | (same as above) |
| `ops.audit_log`, `ops.change_history` | 25 months | drop partitions | `SH_AUDIT_RETENTION_MONTHS` |
| `ops.commands`, `ops.command_items`, `ops.rule_runs` | 25 months | delete by `created_at` / `started_at` | `SH_AUDIT_RETENTION_MONTHS` |
| `ops.outbox` | 7 days after dispatch | delete | — |
| `identity.sessions`, `identity.verifications`, `core.invitations`, `core.connect_states` | 30 days after expiry (connect states: 1 day) | delete | — |
| Facts (`facts.*`) and business mirrors (`orders`, `finance`, `catalog`, `inventory`, `ads`) | until the seller account is deleted | seller-account delete job | — |
| `core.credentials` | until disconnect (row deleted = crypto-shred, ADR-0005) | delete | — |

`maintenance.purge` (nightly, `sh_owner`) applies these; there is no soft delete without a purge rule (trap 18).
Deleting a seller account: status `deleting` → stop syncs → delete facts by `seller_account_id` per partition →
delete the account row (FK cascades remove mirrors, ops and core children).

## 5. PII (D11 = no)

Nothing restricted is stored in MVP. The seam:

- Schema `pii` exists, empty, with no grants to `sh_app`.
- `orders.orders` keeps only coarse geography (`ship_country_code`, `ship_state_or_region`); buyer name, e-mail,
  phone, address lines, city, postal code, buyer PO number and gift messages are dropped by the mapper **before**
  `raw` is written. `finance.financial_event_groups` drops `AccountTail`.
- When PII enters scope (Restricted Data Token, restricted SP-API role): tables `pii.order_buyers`,
  `pii.order_ship_addresses` keyed by `(tenant_id, seller_account_id, order_id)`, every value column encrypted with
  the vault (ADR-0005, separate key kind), a dedicated repository requiring a `PiiAccess` capability, never joined
  into facts, logs or audit, and a scheduled purge 30 days after shipment unless legally required
  (ADR-0009 decision 6, Amazon Data Protection Policy).

## 6. Migrations per slice

P3 turns each section of `db/design` into forward-only SQL migrations in its module
(`modules/<m>/migrations/<UTC timestamp>_<m>_<desc>.sql`, node-pg-migrate, ADR-0009 decision 8). Order:

| Slice | Files (sections) | Module migration owners |
|---|---|---|
| **L0** P3-SCAFFOLD / platform | `00_foundation`, `01_ref` | `packages/db` |
| **L0** P3-IDENTITY (PLT-01) | `02_identity`, `03_core` (tenants … invitations, user_preferences, api_tokens) | platform-auth, platform-tenancy |
| **L0** connections (PLT-03, PLT-04) | `03_core` (connections, credentials, connect_states, ads_profiles, seller_account_marketplaces) | platform-connections |
| **L0** P3-INGEST (PLT-05) | `04_ingest` | ingestion |
| **L0** ads read (ADS-01/02/03) | `05_ads`, `06_facts_ads` (campaign, ad group, target, ad daily) + partitions | ads |
| **L0** writes, audit, rule (PLT-07, PLT-06, AUT-01) | `07_ops` | platform-commands, automation |
| MVP ADS-04..09 | no new tables except `06_facts_ads` search term (ADS-07) and placement (ADS-05) facts | ads |
| MVP PLT-02 | no new tables (rows in core) | platform-connections |
| MVP CAT-01/02 | `08_catalog` | catalog |
| MVP INV-01 | `09_inventory`, `12_facts_ops` inventory daily | inventory |
| MVP ORD-01/02 | `10_orders`, `12_facts_ops` sales daily | orders |
| MVP FIN-01 | `11_finance`, `12_facts_ops` finance per SKU daily | finance |

`99_partitions.sql` is only for this design check; in P3 each module's migration calls
`core.ensure_monthly_partitions` for its own tables.

Notes for P3: `core.apply_tenant_rls`, `core.ensure_monthly_partitions`, `core.touch_updated_at` and the
`core.change_source` enum come first (`00_foundation`). The roles `sh_owner`/`sh_app` are created NOLOGIN; the
deployment sets their login (P6). Better Auth's tables are mapped onto `identity.*` column names by P3-IDENTITY.
